# ذكاء التصميم في مبدع — المنهج الكامل

هذا المستند يوثّق **كيف يعرف المحرك التصميم**. ليس قائمة نصائح عامة، بل قواعد
قابلة للقياس تُطبَّق على كل تصميم: عند التوليد، عند النقد، وعند الإصلاح التلقائي.

الحزمة المسؤولة: `packages/design-knowledge` (بلا اعتماد على شبكة أو نموذج لغوي).
المحرك الحتمي (Tier 1) يعمل كاملاً دون Photoshop أو LLM؛ المهارات هنا هي المصدر
الوحيد للحقيقة، وتُستخدم أيضاً لتغذية أي LLM عبر `SYSTEM_PROMPT`.

---

## 1. لماذا حزمة منفصلة؟

- **فصل المسؤوليات:** `@mubdi/core` يبني الـ Spec، و`@mubdi/design-knowledge`
  يعرف القواعد ويقيسها. لا يوجد استيراد عكسي.
- **قابلية الاختبار:** كل قاعدة دالة نقية (`buildPalette`, `makeTypeScale`,
  `makeGrid`, `evaluateDesign`, `improveSpec`) قابلة للاختبار بلا UI.
- **عدم الانحراف:** نفس الأرقام تُستخدم في التوليد والنقد والإصلاح والتوثيق، فلا
  يمكن أن يقول المولّد شيئاً ويعاقب عليه المُقيّم.

واجهة الاستيراد: `packages/design-knowledge/src/index.ts`.

## 2. المنهج: 10 مجالات مهارة و28 مبدأ

| المجال | لماذا يهم | المبادئ |
|---|---|---|
| التسلسل والتباين | بدون تسلسل لا يعرف القارئ أين يبدأ | hierarchy, contrast, focal-point |
| التخطيط والشبكة | الشبكة تجعل التصميم يبدو محترفاً قبل قراءة الكلمات | alignment, proximity, white-space, grid-8pt, rule-of-thirds, z-pattern |
| نظرية اللون | اللوحة الصحيحة تحمل نصف الرسالة | color-harmony, color-psychology, accent-scarcity |
| الطباعة | الخط صوت التصميم؛ المقياس والمسافة يصنعان الإيقاع | type-scale, measure, repetition |
| العربية وRTL | العربية ليست ترجمة للاتينية | arabic-flow |
| التكوين والتوازن | العين تشعر بالثقل قبل أن تفهمه | balance, imagery, depth |
| الجشطالت | العقل يجمع العناصر تلقائياً | gestalt-proximity |
| الإبداع والفكرة | الزخرفة ليست فكرة | creative-concept, scamper, minimalism, storytelling |
| العلامة والاتساق | العلامة تُبنى بالتكرار | brand-consistency |
| الإنتاج والمنصات | المنصة تقتطع وتضغط | thumb-stopping, safe-zones, production-hygiene |

كل مبدأ في `principles.ts` يحمل: `id`, `nameAr`, `nameEn`, `category`,
`summaryAr` (لماذا)، `rules` (قواعد قابلة للتنفيذ)، ومثالاً مضاداً.
هذه هي المادة التي تُعرض في تقرير المدير الفني تحت «مبادئ مستفادة».

### مسار التعلّم الذي يطبّقه المحرك

1. **الأساسيات** — تباين مقروء، محاذاة واحدة، هامش آمن، شبكة 8.
2. **البنية** — 3–4 مستويات طباعية، بؤرة واحدة، تقارب منطقي، فراغ 25–40%.
3. **التعبير** — لوحة متناغمة، اتجاه فني واضح، صورة تخدم النص، لكنة نادرة.
4. **الإتقان** — عربية سليمة، مقياس متسق، طبقات PSD نظيفة، توازن.
5. **الإبداع** — فكرة في جملة، استعارة واحدة، ثلاثة مسارات مختلفة، قرار جسور.

## 3. نظرية اللون

### 3.1 الفضاء والتناغم

- التحويل يتم عبر HSL (`rgbToHsl` / `hslToRgb`) لأن التحكم في الإضاءة
  والتشبع هو ما يصنع لوحة متماسكة، لا تغيير قنوات RGB عشوائياً.
- أنظمة التناغم المدعومة: `monochrome`, `analogous`, `complementary`,
  `split-complementary`, `triadic`, `tetradic`.
- `classifyPalette(hexes)` يرجع النظام الأقرب + درجة ثقة. إذا كانت الثقة
  < 0.6 يصدر المُقيّم ملاحظة «الألوان لا تتبع علاقة واضحة».

### 3.2 بناء اللوحة بضمانات مقروءة

`buildPalette({ primary, scheme, mode, accent })` يضمن:

| العلاقة | الحد |
|---|---|
| النص على الخلفية | ≥ 7:1 |
| النص الثانوي على الخلفية | ≥ 4.5:1 |
| اللون الأساسي على الخلفية | ≥ 3:1 |
| النص فوق اللون الأساسي (`onPrimary`) | ≥ 4.5:1 |

إن فشل لون في الوصول، يُعدّل `ensureContrast` إضاءته تدريجياً حتى يصل — لا
يُقبل التصميم بلون غير مقروء.

### 3.3 ندرة اللون المميز

- اللون المميز يعمل فقط عندما يكون نادراً (≤ 10–20% من المساحة).
- يقوم المُقيّم بحساب نسبة مساحة الأشكال **المشبعة** فقط (S ≥ 0.2)، ويستثني
  الإطارات والخطوط (فهي حدود لا مساحات) والخلفيات المحايدة.
- عدّ الألوان يحاكي المصمم: **عائلات صبغية + نظام محايد واحد**، لا كل قيمة hex.
  لذلك تدرّج سطحي بنسبة 8% من الخلفية لا يُحسب «لوناً سادساً».

### 3.4 سيكولوجيا اللون

`COLOR_PSYCHOLOGY` يربط كل عائلة لونية بدلالاتها العربية (ثقة، دفء، طاقة…)
وبـ`paletteAdvice` يشرح سبب اختيار اللوحة في تقرير كل نسخة.

## 4. الطباعة

### 4.1 مقياس طباعي لا عشوائية فيه

- `TYPE_SCALES`: minor-second, major-second, minor-third, major-third,
  perfect-fourth, perfect-fifth (نسب موسيقية).
- `makeTypeScale({ canvasMin, scale, minSize })` يبني:
  `display, h1, h2, h3, body, caption, eyebrow, cta`.
- سقف العرض = 12% من ضلع اللوحة الأصغر (لا عنوان يبتلع التصميم).
- أرضية كل المستويات = `minFontSize` الخاص بالمنصة (لا نص غير مقروء على الهاتف).
- `cta` عند ~0.9× من `body`: زر لا ينافس العنوان.

### 4.2 قواعد العربية (بوابة إصدار)

- `tracking = 0` إلزامي للنص المتصل؛ أي تباعد يكسر تشكيل الحروف ويُعد خطأً حرجاً.
- `leading` بين 1.35 و1.8 (الافتراضي 1.45–1.62 حسب الحجم).
- اتجاه `rtl` ومحاذاة يمين؛ الأرقام واللاتينية تُعامل كـ`mixed` عند الحاجة.
- لا أحرف كبيرة (uppercase) للعربية.
- خطوط مسجّلة: Cairo وAlmarai (Regular/Bold) مع بدائل آمنة.

### 4.3 التسلسل

`checkHierarchy(sizes)` يتحقق من:
- 2–4 مستويات فقط.
- نسبة أكبر/أصغر ≥ 2× (المثالي 2.5–4×).
- لا عنصران يتقاسمان أكبر حجم (بؤرة غير حاسمة).

## 5. الشبكة والتخطيط

- `makeGrid` يبني 12 عموداً مع `gutter = snap(margin/2, 8)`.
- **RTL حقيقي:** `inline` معكوسة للقراءة، و`physical` تبقى يسار→يمين للرسم.
- `safeRect` يأخذ اتحاد الهامش مع مساحات المنصة (ستوري: أعلى 120 / أسفل 200).
- `SPACING_SCALE = [0,4,8,12,16,24,32,48,64,96,128,160]`.
- `alignRectX` + `columnSpan` يمنعان محاذاة "تقريبية": إما بداية أو وسط أو نهاية.

### 5.1 11 نموذج تكوين

`poster-stack, editorial-stack, hero-center, minimal-frame, split-diagonal,
event-poster, thumbnail-bold, cinematic-bleed, story-stack, magazine-cover,
quote-card`.

كل نموذج يخرج `LayoutPlan` يحتوي: الكتل النصية بأحجامها ومحاذاتها، الأشكال
المساندة، مسار القراءة، البؤرة، و**مبرر الفكرة** (`rationaleAr`). التكوين ليس
قوالب ثابتة؛ الكتل تُقاس بـ`measureTextWidth` ثم تُوزّع على الشبكة.

### 5.2 ضمانات ضد الأخطاء الشائعة

- لا نص يلامس الحافة (`clampTextLayers`).
- لا كتلة تخرج من المستطيل الآمن.
- زر CTA وخلفيته يتحركان معاً (لا نص يطفو خارج الزر).
- الأشكال الزخرفية لا تُحسب كمساحة نص.

## 6. الاتجاهات الفنية (Art Directions)

عشرة اتجاهات، كل واحد شخصية كاملة وليس فلتراً:

| id | الاسم | الطابع |
|---|---|---|
| editorial | تحريري | شبكة صارمة، غلاف مجلة |
| bold-type | طباعي جسور | العنوان هو الصورة |
| minimal | بسيط | فراغ وثقة |
| luxury | فخم | كحلي/ذهبي، خطوط رفيعة |
| youthful | شبابي | ألوان مشبعة، حركة |
| tech | تقني | تدرجات، شبكات |
| organic | عضوي | أشكال ناعمة، دفء |
| heritage | تراثي معاصر | زخرفة مبسطة، هوية عربية |
| brutalist | بروتالي | تباين صارخ، بلا زخرفة |
| cinematic | سينمائي | صورة كاملة وتعتيم متدرج |

كل اتجاه يحدد: التناغم اللوني، الوضع (فاتح/داكن)، المقياس الطباعي، اقتران
الخطوط، النماذج التكوينية المفضلة، لغة الأشكال، معالجة الصور، ونبرة النص.

**التنوّع مضمون:** الاتجاهات مقسّمة إلى عائلات (clean / bold / elegant / organic)،
ولا يختار المحرك اتجاهين من عائلة واحدة في نفس المجموعة. لذلك النسخ الثلاث
تختلف في الفكرة واللوحة والتكوين، لا في درجة اللون فقط.

## 7. الإبداع

### 7.1 مسارات المفاهيم (10)

`generateConcepts(brief, n)` يرتّب أفكاراً كاملة لا قوالب:

كلمة واحدة بطلة، الرقم هو البطل، الفراغ يحكي، توتر الانقسام، شيء يمثل الفكرة،
حقل نمط، نظرة إنسان، شريط حكاية، قصّ متطرف، كولاج مقصوص.

كل مسار يحدد: الفكرة بجملة، الجهاز البصري، زاوية النص، **والمخاطرة**. المخاطرة
المعلنة هي ما يفرّق المدير الفني عن منفّذ الطلبات.

### 7.2 SCAMPER عند طلب «فكرة أخرى»

استبدل، ادمج، كيّف، عدّل، استخدم بشكل آخر، احذف، اعكس — سبعة أسئلة جاهزة.

### 7.3 زوايا العنوان

`headlineAngles` تولّد 6 صيغ (وعد مباشر، سؤال، رقم، قبل/بعد، دعوة، اختصار)
لجعل النص يقوم بنصف العمل التصميمي.

## 8. التقييم (Rubric)

### 8.1 القياسات

| القياس | كيف يُحسب | الحد |
|---|---|---|
| أدنى تباين | WCAG لكل طبقة نصية على خلفيتها الفعلية (بعد الشفافية والتدرج، ونص الزر على درجته لا على خلفية الصفحة) | 4.5 / 3 حسب الحجم |
| تباين التسلسل | أكبر حجم ÷ أصغر حجم (بلا الشعار) | ≥ 2× |
| مستويات الخط | أحجام مميزة | 2–4 |
| المسافات على الشبكة | نسبة الفراغات (≤96px) المطابقة للمقياس ±3 | ≥ 80% |
| حواف المحاذاة | حواف بداية مجمّعة بسماحية 4px؛ النص المركزي يُقاس بمركزه | ≤ 3 |
| انحراف مركز الثقل | مركز الثقل المرجّح بالمساحة والتباين عن مركز الإطار | ≤ 18% |
| كثافة النص | **حبر النص**: عرض السطر المقاس × الحجم × ارتفاع السطر | ≤ 40% |
| عدد الألوان | عائلات صبغية + نظام محايد (داكن/فاتح) | ≤ 5 |
| عائلات الخطوط | بلا لاحقة `-Bold` | ≤ 2 |
| اختراقات الأمان | طبقة نصية داخل منطقة محجوزة | 0 |

**لماذا حبر النص؟** صندوق نص بعرض عمود كامل وعنوان قصير ليس 40% من الإطار.
القياس بالحبر يمنع الإنذارات الكاذبة التي تجعل التقرير غير موثوق.

**لماذا تُستثنى الفراغات الكبيرة؟** الفراغ بين الهيدر والفوتر قرار تكويني مقصود،
وليس خللاً في الإيقاع. تُقاس فقط الفراغات ≤ 96px.

### 8.2 الأوزان

| الفئة | الوزن |
|---|---|
| التباين والقراءة | 18 |
| التسلسل البصري | 15 |
| الإيقاع والمسافات | 12 |
| المحاذاة والشبكة | 12 |
| التوازن | 10 |
| اللون | 10 |
| الفراغ والكثافة | 8 |
| الطباعة | 8 |
| المنصة والإنتاج | 7 |

### 8.3 سقوف الدرجة

المتوسط المرجّح وحده يسمح لمشكلة حرجة واحدة أن تختبئ خلف تسع فئات نظيفة.
لذلك:

- مشكلتان حرجتان → السقف 62.
- مشكلة حرجة واحدة → السقف 79.
- ثلاث مشكلات رئيسية → السقف 84.

تصميم غير مقروء لا يمكن أن يكون «ممتازاً» لأن مسافاته جميلة.

### 8.4 التقديرات

`A+ ≥95, A ≥90, B ≥80, C ≥70, D ≥60, F` — بعربية: احترافي، ممتاز، جيد جداً،
جيد، مقبول، يحتاج مراجعة.

## 9. المدير الفني (Coach)

`coach(evaluation, brief)` يحوّل الأرقام إلى محادثة:

- ملخص + تقدير.
- ما يعمل جيداً (الفئات ≥ 85).
- أولويات مرتبة بالخطورة ثم بالقياس المقاس، كل واحدة بـ: ماذا، كيف تصلح، **ولماذا**
  (نص المبدأ).
- مبادئ مستفادة (تعليم لا لوم).
- جدول القياسات مع ✓/✗.
- خطوات تالية عملية.

`explainDesign` يشرح كل نسخة قبل النقد: الاتجاه، الفكرة، اللوحة، الطباعة،
التكوين، وموضع البؤرة.

## 10. الإصلاح التلقائي

`improveSpec(spec, brief, preset, { maxIterations, targetScore, keepBest })`

حلقة محافظة: تقيس → تصلح ما يمكن إثباته → تعيد القياس → تحتفظ بالأفضل.
إذا انخفضت النتيجة تُلغى الجولة (لا تحسين بالتخمين).

الإصلاحات المدعومة:

1. **التباين** — رفع إضاءة النص حتى يصل الحد المطلوب.
2. **تباعد العربية** — تصفير `tracking`.
3. **أرضية الخط** — رفع أي حجم تحت حد المنصة.
4. **سلّم التسلسل** — إعادة بناء الدرجات من العنوان: 1×، 1/1.35، 1/2، 1/2.9.
5. **الإيقاع** — تقريب الفراغات الصغيرة (≤6px) إلى مقياس 8.
6. **المحاذاة** — دفع الحواف القريبة (≤8px) إلى هامش المحتوى.
7. **مساحات الأمان** — إعادة الكتل داخل المستطيل الآمن (مع شريك CTA).

الإصلاح يعيد `before/after/steps/improved` ليُعرض للمستخدم ماذا تغيّر بالضبط.

## 11. واجهات الاستخدام

```ts
import {
  generateConcepts, coach, evaluateDesign, improveSpec,
  knowledgeSnapshot, SYSTEM_PROMPT, THRESHOLDS, ART_DIRECTIONS,
} from '@mubdi/design-knowledge';

import { generateVariantDetails, generateVariantSet } from '@mubdi/core';
```

- `generateVariantSet(brief, presetId, { name })` → 3 نسخ، كل واحدة تحمل
  `directionId/NameAr`, `archetype`, `rationaleAr`, `paletteSummaryAr`.
- `critiqueSpec(spec, brief)` → `{ score, gradeAr, evaluation, coach, reportAr }`.
- `knowledgeSnapshot()` → المنهج كاملاً كـJSON (للوحة المساعدة أو لـAPI).
- `SYSTEM_PROMPT` → نفس القواعد جاهزة لأي LLM يكتب نصاً أو ينقد.

## 13. كيف تضيف مهارة جديدة

1. **مبدأ جديد:** أضف كائناً في `principles.ts` (`id`, `category`, عربي/إنجليزي،
   `rules`, مثال مضاد). سيظهر تلقائياً في `knowledgeSnapshot` والمنهج.
2. **اتجاه فني:** أضف كائناً في `direction.ts` ثم أضفه إلى `DIRECTION_FAMILY`
   وإلى `DIRECTION_PRIMARY` في `packages/core/src/spec.ts`.
3. **نموذج تكوين:** اكتب دالة `(ctx: Ctx) => LayoutPlan` وسجّلها في `ARCHETYPES`.
4. **قياس جديد:** أضف حقلاً في `DesignMetrics`، احسبه في `evaluateDesign`،
   وأضف له إصلاحاً في `improve.ts` وشرحاً في `coach.ts`.
5. **اختبار:** أضف حالة في `tests/design-knowledge.test.ts` تثبت القاعدة
   (حالة ناجحة + حالة فاشلة). لا تُقبل مهارة بلا اختبار.

## 14. الحدود المعروفة

- القياسات هندسية/لونية، وليست تحليلاً بصرياً للبكسل: لا تكتشف صوراً رديئة
  الجودة أو وجوهاً مشوّهة.
- الجمالية الذاتية (ذوق العميل) لا تُقاس؛ الـRubric يقيس الاتساق والقراءة
  والبنية، ويترك القرار النهائي للمستخدم.
- التقييم يعتمد على `measureTextWidth` التقريبي (متوسط عرض الحرف) لأن القياس
  الحقيقي يحتاج رسم الخط؛ الفارق صغير لكنه ليس صفراً.
- تحليل الصور الفعلية (سيكولوجيا الصورة، تكوين الكادر) ما زال في خارطة الطريق.
